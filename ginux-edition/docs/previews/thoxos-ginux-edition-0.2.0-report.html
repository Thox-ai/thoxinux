ThoxOS Ginux Edition now builds Azure VM images. 02Azure Virtual Desktop and this image

Microsoft's guide prepares a Windows golden image for AVD host pools. AVD session hosts run Windows 11 or 10 Enterprise and Windows Server only, so a Linux image cannot join a host pool. The ThoxOS image follows the same golden-image steps and deploys as a standard Azure VM reached over RDP.

Guide step (Windows)ThoxOS image (Linux)
Windows 10 Enterprise multi-sessionDebian 13 with the Azure cloud kernel
Generation 1 VM, fixed VHDGeneration 2 (UEFI), fixed VHD built offline, MiB-aligned
Office, FSLogix, Defender, Windows UpdateHyper-V drivers, cloud-init, Azure agent, serial console, PTP time
Sysprep generalizeNever booted before upload: empty machine-id, no host keys, no account
Upload and create an imagePage blob and Azure Compute Gallery image version
Host poolazuredeploy.json VM; a Windows host pool can publish a RemoteApp to it if AVD is required
Security typeStandard, not Trusted Launch: the systemd-boot loader is unsigned. A signed loader is queued before Trusted Launch can be claimed.

05Deploy on Azure

  1. Build the VHD: installer/build-host-image.sh --target azure --desktop desktop (about 2 minutes with a warm Docker cache).
  2. Publish: azure/publish-image.sh --vhd build/azure/thoxos-ginux-azure-desktop-0.2.0.vhd --resource-group thoxos-images --location eastus. It prints the image version ID.
  3. Deploy: az deployment group create with azure/azuredeploy.json, the image version ID, allowedSourceCidr set to your address and an administrator password.
  4. Connect with RDP to the VM's DNS name; pick a look; open ThoxOS on Ginux from the dock.
  5. Optional: set aiUpstream, aiAuth, aiApiKey and aiModel to route thox ask to a hosted model.
ExposureSSH and RDP open only to the one source range you pass; there is no default. Ginux has no security audit: keep it a research VM.

06Two records, kept apart

A second runtime answered the same request in pull request #2: an Ubuntu 24.04 marketplace host with a bootstrap artifact, a private VM behind NAT, Trusted Launch, a kernel startup patch with five fixes plus an Azure profile patch, and no desktop. The two records agree that AVD cannot host Ginux and that nothing ran on Azure. They differ on image strategy, security type, exposure and the kernel patch set. RECONCILIATION_2026-10-29.md lists each point for a ruling; neither record was changed to match the other.
