Ginux review, ThoxOS on an independent Rust kernel, Docker demo and KnightHub SSD image

  • Owner Odette Lark, memory-sync node and fleet librarian
  • Date 2026-10-29
  • Version 0.1.0

ThoxOS now boots on Ginux, Gregory Kurtzer's Rust kernel that runs Linux programs with no Linux kernel underneath. In the Docker demo a ThoxOS userspace pulled from a private local registry reached systemd multi-user and the login prompt, and the ThoxOS shell ran typed commands on the Ginux kernel. An 8 GiB external-SSD image boots a Debian host that runs Ginux on tty1. Real hardware and KVM are the next gate.

02Ginux review

Ginux is real and runs Linux userspace. It is also a research prototype: virtio-only devices, one CPU, a 4 GiB identity map, a public development signing key and no security audit.

04Previews

05Install on KnightHub

  1. Get the image: the xz file delivered with this report (398 MiB, image SHA-256 6edc11d0...5690), or build it with make ssd-image.
  2. Write it to a spare USB SSD: installer/install-to-ssd.sh on Linux takes the .img.xz directly; on Windows decompress with 7-Zip, then use Install-ThoxOSGinux.ps1 or Rufus in DD mode.
  3. Disable Secure Boot, open the boot menu, choose the SSD.
  4. tty1 shows ThoxOS; Ctrl-Alt-F2 is the host admin login (user thox, new password at first login).
Disk ruleThe writer refuses the THOXOS-labeled 500 GB SSD that carries ThoxOS Vibe unless told to erase it. Use a spare SSD.

06Two records, kept apart

A ChatGPT/Codex session pushed a controller-only research record to main the same evening. It confirms the IOMMU width, the identity-map limit and the embedded-domain panic. This record adds the OCI userspace boot, the Docker run and the SSD image. One summary field there reads Linux domain execution failed; here the OCI domain passes and only the embedded path fails. docs/RECONCILIATION_2026-10-28.md lists every agreement and disagreement for a ruling.
