# Decision log

Decisions made under Autonomous Ship Mode for ThoxOS Ginux Edition 0.1.0. Each one stands until Tommy rules otherwise.

| # | Date | Decision | Why | Reversible by |
|---|---|---|---|---|
| D1 | 2026-10-28 | KnightHub boots a Debian 13 host from the SSD and runs Ginux under KVM; bare-metal Ginux is only an experimental boot entry | Ginux drives only QEMU virtio devices and a serial console (REVIEW F-table, hardware profile). Bare metal cannot reach NVMe, USB or the NIC | A Ginux release with physical drivers |
| D2 | 2026-10-28 | ThoxOS userspace = Rocky 10 UBI init (upstream-validated digest) plus a file-only overlay and one demo user | The only userspace upstream boots through `multi-user.target`; adding packages risks units Ginux cannot run | Upstream validating other bases |
| D3 | 2026-10-28 | Serve the userspace from a local, read-only TLS registry trusted through a per-build root scoped to one host name (patch 0003) | Ginux pulls only over HTTPS from pinned roots; publishing to Docker Hub would need an account decision and public exposure | Tommy choosing a public Docker Hub namespace |
| D4 | 2026-10-28 | Destroy the local root key right after signing the registry leaf | A trusted root that cannot sign anything new cannot be abused later | None needed |
| D5 | 2026-10-28 | Pin QEMU 11.1 from trixie-backports in the demo and on the host | QEMU 10.0.13 fails Ginux virtio-net init; 10.2.2 and 11.1.2 pass (F3) | Upstream fix for F3 |
| D6 | 2026-10-28 | Cap VM RAM at 2816 MiB, default 2 GiB | Ginux identity-maps 4 GiB; q35 moves RAM high above 2.75 GiB (F5) | Ginux mapping all RAM |
| D7 | 2026-10-28 | Ship patches 0001-0003 only; hold the partial fix for F4 | A fix that still fails its own check is not shippable; ThoxOS never uses the embedded minimal system | Completing the F4 fix |
| D8 | 2026-10-28 | thoxos-g quits on Ctrl-A then X, not Ctrl-] | Ctrl-] is Ginux's own detach key | None needed |
| D9 | 2026-10-28 | Browser console: one client, credential generated per container unless set, bound by `make demo-web` to 127.0.0.1 | Each connection boots a VM on the same volume; no default password on a network port | None needed |
| D10 | 2026-10-28 | SSD installer refuses a disk carrying a THOXOS label unless `--erase-existing-thoxos` | The ThoxOS Vibe Desktop plan uses a 500 GB SSD labeled THOXOS; never erase it silently | Tommy choosing the target disk |
| D11 | 2026-10-28 | systemd-boot, Secure Boot off | Simplest UEFI path from an offline build; KnightHub already boots an external Linux SSD for ThoxOS Vibe (assumption stated in the user guide) | Signed shim path in the dev queue |
| D12 | 2026-10-28 | Repository license Apache-2.0, THOX trademarks reserved in NOTICE.md | Matches upstream Ginux so patches and tooling combine cleanly; trademarks are outside Apache grants | Tommy ruling a different license for THOX-authored files |
| D13 | 2026-10-28 | No AI model ships in the image; `thox ask` targets the host endpoint at 10.0.2.2:11434 and needs `THOX_AI_MODEL` set | The KnightHub model endpoint is planned, not confirmed; a guessed model name would be invented data | Tommy naming the served model |
| D14 | 2026-10-29 | Interactive ThoxOS runs in a second domain whose init is `thox-shell`, a small line editor that reads the console byte by byte and runs each line with `bash -c`; KnightHub tty1 defaults to it | Measured: getty login never reaches a password prompt and bash as init exits at its first read (V9); `thox-shell` passes the e2e session (V12). Upstream itself validates shells as domain init | Upstream console line discipline |
| D15 | 2026-10-29 | Replace the Ginux volume when the served userspace manifest changes | Ginux answers from its OCI cache by tag (F12); the volume holds only that cache and the domain table, which the boot sequence recreates | Ginux checking the registry digest before a cache hit |
| D16 | 2026-10-29 | Version the host images 0.2.0; the guest (Ginux kernel from the same pinned source and patches, ThoxOS userspace) stays 0.1.0 | The guest did not change in behavior; only the host gained targets. `HOST_VERSION` names images, `VERSION` names the guest | A guest change |
| D17 | 2026-10-29 | Azure deployment is a Gen2 Linux VM from an Azure Compute Gallery image, following the golden-image flow of Microsoft's AVD master-image guide | Azure Virtual Desktop session hosts must run Windows (AVD prerequisites list no Linux); the guide's steps map onto a Linux image (AZURE.md) | An AVD host pool with a RemoteApp to the ThoxOS VM, if AVD is required |
| D18 | 2026-10-29 | The desktop is the TXF 5.2 ThoxOS Desktop variant (Debian 13, looks Slate, Porcelain, Console Pro) on XFCE 4.20 | It is the registered TXF variant whose base matches this host. XFCE with xrdp is the RDP desktop that works on Debian without GPU; Vibe (COSMIC) and Plasma are separate variants and are not copied | A Plasma or GNOME build of the same looks |
| D19 | 2026-10-29 | Keep the desktop implementation in `ginux-edition/desktop/` and flag the location | TXF names `ttracx/thoxos-desktop` canonical, but that tree holds Ubuntu 26.10 + Plasma tooling and no Debian 13 implementation | Tommy ruling where the implementation lives |
| D20 | 2026-10-29 | Azure images use `linux-image-cloud-amd64`; KnightHub keeps `linux-image-amd64` | The cloud kernel carries the Hyper-V drivers and KVM and drops hardware drivers Azure never needs | None needed |
| D21 | 2026-10-29 | No `rootdelay` on the Azure command line | Microsoft's generic guidance sets `rootdelay=300`, but Debian's initramfs-tools sleeps for the full value (measured: boot paused 300 s after "Loading essential drivers"); it waits for the root device anyway | None needed |
| D22 | 2026-10-29 | Accelerated networking off in the template; Mellanox and MANA virtual functions marked unmanaged | A VF enslaved to hv_netvsc must not get its own DHCP lease; off is the simple safe default for a research VM | Enabling it after a tested image |
| D23 | 2026-10-29 | Desktop images run one Ginux VM per user (`thoxos-ginux`, state in `~/.local/state/thoxos-g`); the tty1 console service is off on desktop images | Several RDP users can each run ThoxOS; a shared VM would hold the single-instance lock for everyone | None needed |
| D24 | 2026-10-29 | Hosted AI goes through `thox-ai-relay` on 127.0.0.1:11434, off until `/etc/thoxos/ai-relay.env` exists | Keeps the key on the host (root:thoxos-ai 0640), out of user shells and the Ginux guest, and reuses the port the guest already targets | A per-user credential model |
| D25 | 2026-10-29 | Default VM size `Standard_D4s_v5` | Dsv5 sizes support nested virtualization, so Ginux can use KVM; 16 GiB fits several 2 GiB Ginux VMs | Azure test results on other sizes |
| D26 | 2026-10-29 | Deployable template is ARM JSON (`azure/azuredeploy.json`) | The Bicep compiler could not be fetched in this runtime, so a Bicep source could not be compiled or checked; ARM JSON deploys from the CLI and the portal as is | Adding Bicep with a compile check in CI |
| D27 | 2026-10-29 | The xrdp login box uses the Porcelain (light) values over the dark wallpaper | xrdp draws its labels in its "black" color, so a dark box would hide them | None needed |
| D28 | 2026-10-29 | xfwm4 keeps compositing with `vblank_mode=off` and no dock shadow | RDP sessions have no vblank source; the dock shadow outlined plank's full-width window as a line across the desktop | A GPU-backed VM size |
| D29 | 2026-10-29 | The Azure overlay tags the UEFI framebuffer `master-of-seat` | The cloud kernel has no DRM drivers. systemd's hwdb already tags the Hyper-V framebuffer, so Azure gets the console greeter; the rule gives other UEFI hypervisors (QEMU, Proxmox) the same | A cloud kernel with simpledrm |
| D30 | 2026-10-29 | `plymouth.ignore-serial-consoles` on the Azure desktop command line | With `console=ttyS0` Plymouth falls back to text everywhere; this keeps the graphical splash on screen while the serial log stays complete for boot diagnostics | None needed |
| D31 | 2026-10-29 | Keep this Azure variant separate from Record A's (pull request #2) and compare them in `docs/RECONCILIATION_2026-10-29.md` | Two runtimes answered the same request with different hosts, kernels and network postures; merging them would blend two records into one | Tommy's ruling |
| D32 | 2026-10-29 | No GitHub Actions. CI runs locally (`scripts/local-ci.sh`, `make ci`), a pre-push hook gates pushes, and `make ci-report` posts the result as the `thox/local-ci` commit status. The Actions workflow is removed | Tommy: Actions is too expensive; every run already ended `startup_failure` (VALIDATION V19). Commit statuses cost nothing and still show on pull requests | A self-hosted runner on a THOX machine if unattended CI is ever needed |
